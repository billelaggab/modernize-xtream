# مدار | Madar Stream Control

منصة **جديدة بالكامل** لإدارة البث المباشر والفيديو عند الطلب، مستوحاة من احتياجات مستخدمي [xtreamui_mirror](https://github.com/emre1393/xtreamui_mirror)، وليست نسخة معدّلة من ملفات Xtream القديمة. يعمل المشروع على Ubuntu **24.04** و **26.04** بحاويات مستقلة، دون Python 2 أو PHP قديم أو حزم `libcurl3` / `libpng12` أو ملفات ثنائية مجهولة المصدر.

> استخدم المنصة فقط لبث محتوى تملك حقوق توزيعه. لا تتضمن قنوات أو مصادر فيديو أو وسائل لتجاوز DRM.

## ما الذي يعمل الآن؟

- لوحة إدارة عربية باتجاه RTL، عرض أولي توضيحي قبل إنشاء حساب المدير، ثم مساحة عمل حقيقية في PostgreSQL.
- حساب مدير، كلمات مرور مجزّأة بـ scrypt، جلسات HTTP-only، رمز تهيئة أولي، وتسجيل أحداث الإدارة.
- إضافة وتعديل وحذف وإيقاف القنوات المباشرة والفيديو عند الطلب، وتصنيفاتها، وتعيينها على خوادم البث.
- إضافة خوادم Origin / Edge ومتابعة النبضات وحالة كل بث.
- إضافة المشتركين وإيقافهم وتعديل صلاحية الاشتراك وتجديد رمز الوصول. يظهر رابط القائمة **مرة واحدة** عند الإنشاء أو التجديد؛ يُخزَّن تجزئته فقط.
- قائمة M3U خاصة لكل مشترك، وبوابة HLS تتحقق من صلاحية الرابط لكل طلب قبل جلب المقاطع من الوكيل.
- وكيل Python 3 / FastAPI يزامن القنوات مع اللوحة ويشغّل FFmpeg بدون shell، ويجهز مقاطع HLS الحية أو VOD.
- ترحيل قاعدة البيانات بمهاجرات Drizzle المولّدة، وDocker Compose لتشغيل PostgreSQL واللوحة والوكيل.

## البنية

| المكوّن | التقنية | الوظيفة |
|---|---|---|
| `src/app`, `src/components` | Next.js 16 + React + TypeScript | واجهة الإدارة وواجهات API |
| `src/db`, `drizzle` | PostgreSQL 16 + Drizzle ORM | البيانات والجلسات والترحيلات |
| `agent/main.py` | Python 3.12+ + FastAPI + HTTPX + FFmpeg | مزامنة المصادر وتحويلها إلى HLS |
| `scripts/install.py` | Python 3.12+ / stdlib | فحص Ubuntu، توليد الأسرار، تشغيل Compose |

تستخدم صورة الوكيل Python 3.12 مستقلًا عن نسخة Python الخاصة بالنظام؛ بذلك يعمل التصميم نفسه على Ubuntu 24.04 و26.04 دون تغيير `/usr/bin/python3`.

## التثبيت على Ubuntu 24.04 أو 26.04

المتطلبات: جهاز 64-bit، Python 3.12 أو أحدث، اتصال بالإنترنت، وصلاحية `sudo`. ثبّت Docker Engine مع Compose Plugin باتباع [التعليمات الرسمية لـ Docker على Ubuntu](https://docs.docker.com/engine/install/ubuntu/)، **أو** دع المثبّت يثبت الحزم من مستودع Docker الرسمي الموقّع عبر `--install-docker` (لا ينفّذ `curl | bash`).

```bash
# داخل نسخة هذا المشروع على الخادم:
sudo python3 scripts/install.py check --install-docker
sudo python3 scripts/install.py install
```

أو في أمر واحد على خادم جديد:

```bash
sudo python3 scripts/install.py install --install-docker
```

ينشئ المُثبّت `deploy/.env` بصلاحيات `0600`، ويطبع **رمز التهيئة** مرة واحدة. احفظ الرمز. يبدأ PostgreSQL واللوحة والوكيل، ويطبّق ترحيلات قاعدة البيانات تلقائيًا. لا ينسخ أي ملف من `xtreamui_mirror`.

**الوصول الافتراضي آمن ومحلي:** تعمل اللوحة على `http://127.0.0.1:3000` فقط. للاتصال من حاسوبك دون نشر المنفذ:

```bash
ssh -L 3000:127.0.0.1:3000 user@your-server
# افتح http://localhost:3000 في متصفحك
```

اضغط **ابدأ الآن**، أنشئ حساب المدير وأدخل `SETUP_KEY` الذي طُبع عند التثبيت. تظهر بيانات تجريبية قبل إنشاء الحساب **فقط**؛ مساحة العمل الحقيقية تبدأ فارغة.

**مهم — قاعدة بيانات المعاينة مؤقتة:** في بيئات المعاينة السحابية تُعاد قاعدة البيانات مع كل إعادة تشغيل، فيختفي حساب المدير وتحتاج إلى إعادة إنشائه. على الخادم الفعلي تبقى البيانات محفوظة دائمًا في حجم `postgres_data` ولا تتأثر بإعادة التشغيل أو إعادة البناء.

### أول بث فعلي

1. من **الخوادم** أضف الخادم الرئيسي بعنوان `http://agent:9000`. إذا كان أول خادم فسيكون رقمه `1`، وهو `NODE_ID=1` الافتراضي. إذا اختلف الرقم، غيّر `NODE_ID` في `deploy/.env` ثم شغّل `sudo docker compose --env-file deploy/.env up -d`.
2. من **القنوات المباشرة** أو **مكتبة الفيديو** أضف رابط مصدر HTTP(S) تملك حق بثه، وحدد الخادم. يدعم FFmpeg عادةً MPEG-TS وMP4 وHLS؛ الوضع الافتراضي `-c copy` يتطلب ترميزات متوافقة مع HLS لدى المشاهدين (عادة H.264/AAC).
3. من **المشتركون** أنشئ مشتركًا واحفظ رابط M3U الذي يظهر مرة واحدة. الصلاحية والإيقاف يُتحقّق منهما عند كل طلب مقطع.

**مهم للنشر العام:** ضع وكيل HTTPS عكسيًا (مثل Nginx أو Caddy) أمام المنفذ المحلي، ثم عيّن `PANEL_PUBLIC_URL=https://your-domain.example` في `deploy/.env` وأعد تشغيل اللوحة. لا تُعرّض الوكيل أو قاعدة البيانات للإنترنت؛ هما داخل شبكة Docker فقط. امنع تسجيل مسارات `/api/playlist` و`/api/watch` في سجلات الوكيل العكسي لأنها تحمل رموز المشتركين في الرابط. احتفظ بنسخة احتياطية من `deploy/.env` وبيانات PostgreSQL.

## التطوير محليًا

يتطلب Node.js 22+، PostgreSQL، وملف `.env` يحوي `DATABASE_URL` (انظر `src/db/index.ts`).

```bash
cp .env.example .env
# عدّل DATABASE_URL وAGENT_TOKEN وSETUP_KEY بقيمك الخاصة
npm ci
npx drizzle-kit migrate
npm run dev
```

وكيل Python محليًا، عند الحاجة، على خادم يملك FFmpeg:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r agent/requirements.txt
# ثبّت ffmpeg باستخدام مدير حزم النظام
export PANEL_URL=http://127.0.0.1:3000
export AGENT_TOKEN='<نفس القيمة التي تستخدمها اللوحة>'
export NODE_ID=1
export HLS_ROOT="$PWD/.hls"
uvicorn agent.main:app --host 127.0.0.1 --port 9000
```

إذا شغّلت الوكيل محليًا خارج Docker فاجعل عنوان الخادم في اللوحة `http://127.0.0.1:9000`؛ داخل Compose استخدم `http://agent:9000`. لتشغيل وكيل على خادم ثانٍ، استخدم شبكة خاصة/VPN وعنوانًا يمكن للوحة الوصول إليه، وعيّن `NODE_ID` ليطابق رقم الخادم الجديد. لا تفتح منفذ الوكيل علنًا.

### فحوص مفيدة

```bash
python3 -m compileall -q agent scripts
npx next typegen
npm exec tsc -- --noEmit
npm run build
curl -fsS http://127.0.0.1:3000/api/health
sudo python3 scripts/install.py status
```

## أين أجد رمز التهيئة (SETUP_KEY)؟

- **على الخادم:** يُطبع **مرة واحدة** في شاشة الطرفية عند أول تشغيل لـ `scripts/install.py install`، ثم يُحفظ في `deploy/.env` (صلاحيات 0600). استرجاعه لاحقًا: `sudo grep SETUP_KEY deploy/.env`.
- **في معاينة المنصة:** يُقرأ من إعدادات بيئة الجلسة (المتغيرات السرية). إن لم تضبطه، اترك حقل «رمز التهيئة» فارغًا.
- **إن ضاع الرمز:** استبدله بقيمة عشوائية جديدة في `deploy/.env` (أو في إعدادات البيئة هنا) ثم أعد تشغيل اللوحة: `sudo docker compose --env-file deploy/.env up -d panel`. لا حاجة لأي ترحيل؛ يُستخدم الرمز في إنشاء حساب المدير أول مرة فقط.

## حدود النسخة الأولى

هذه **إعادة بناء مستقلة** وليست ترقية مباشرة للوحة XtreamUI R22F. لا تستورد قواعد بيانات Xtream القديمة ولا تدعم `player_api.php` أو روابط المستخدم/كلمة المرور القديمة. لا تتضمن EPG أو DRM أو إعادة ترميز متعددة الدقات أو موازنة تلقائية للأحمال. حقول Origin/Edge تنظم العقد وتعيين البث، لكنها ليست موازن حمل ذكيًا. يُسجَّل عدد طلبات قائمة التشغيل لا عدد المشاهدين المتزامنين، ولا يوجد حد جلسات متزامنة. مرّر حركة بث كثيفة عبر CDN/Reverse Proxy مناسب بدل الاعتماد على بوابة Next.js وحدها.

مستودع المرآة الأصلي عبارة عن **مثبّت Python 2** ينزل أرشيفات وباينري قديمة ويدعم Ubuntu 16/18 فقط؛ لذلك لم نستخدم ملفات إصداراته المغلقة أو سكربت تثبيته، ولم ندّعِ توافقًا مباشرًا مع قاعدة بياناته أو واجهاته.
